# Руководство пользователя Densito-AI

Для врача-эксперта (рентгенолога) и администратора. Как установить сервис —
[РАЗВЁРТЫВАНИЕ.md](РАЗВЁРТЫВАНИЕ.md).

Сервис — помощник по контролю качества денситометрии: он не ставит диагноз,
а проверяет, можно ли использовать исследование для клинической
интерпретации, и объясняет, что с ним не так. Решение всегда остаётся за
специалистом.

## 1. Вход

Откройте веб-интерфейс (по умолчанию `http://<адрес сервера>:5173`) и войдите.

| Роль | Демо-логин | Что доступно |
|---|---|---|
| Эксперт | `expert` | загрузка и анализ исследований, экспертная проверка |
| Администратор | `admin` | всё то же + пользователи, справочник нарушений, статистика, журнал действий |

Пароли демо-учёток задаёт администратор при установке (по умолчанию
`expert12345` и `admin12345`).

**Индикатор ИИ-модуля** в шапке (справа, рядом с именем пользователя):

- зелёный **«ИИ-модуль готов»** — анализ можно запускать;
- красный **«ИИ-модуль недоступен»** — сервер работает, но какая-то часть модуля
  не загрузилась (например, нет файла весов); кнопки анализа и пакетной
  обработки неактивны;
- красный **«Сервер недоступен»** — нет связи с backend.

Нажмите на индикатор, чтобы увидеть версию модели и состояние каждой части:
правила ТЗ, модели позвоночника, нейросеть укладки бедра. Проверка повторяется
каждые 30 секунд, кнопка **«Проверить»** — сразу.

## 2. Список исследований

Раздел **«Исследования»** — все загруженные исследования: ID, дата, область,
**«Статус обработки»**, **«Итоговая оценка»** («Качественное» / «Есть
нарушения»), число нарушений, **«Экспертная проверка»** и отметка
**«Обезличено»**.

- **Поиск по ID, описанию, области** и фильтры по статусам и оценке — над таблицей.
- Плашки над таблицей — сводка: всего исследований, с нарушениями, ожидают
  проверки, проверено экспертом.
- **«Нет»** в колонке «Обезличено» — в DICOM-тегах найдены персональные
  данные (ФИО, дата рождения и т.п.). Такое исследование лучше не хранить в
  сервисе.

## 3. Загрузка исследования

Кнопка **«Загрузить DICOM / ZIP»**:
- один DICOM-файл — одно исследование;
- zip-архив — снимки группируются по идентификатору исследования
  (StudyInstanceUID): снимки одного исследования попадают в одну карточку
  (обычно 1–3 снимка: позвоночник и одно-два бедра), а если в архиве несколько
  исследований — по каждому создаётся своя карточка, и сервис сообщает, сколько
  их получилось. Файл без идентификатора исследования получает отдельную карточку;
- пустые и не-DICOM файлы (нет размеров или пиксельных данных) отклоняются, в
  архиве — пропускаются.

Для пакетной проверки большого набора с выгрузкой общей таблицы используйте
пакетную обработку (раздел 7), а не загрузку по одному.

## 4. ИИ-анализ и результат

Откройте исследование и нажмите **«Запустить ИИ-анализ»** (анализ занимает
доли секунды на снимок). В карточке появятся:

- в блоке **«Снимки»** — анатомическая область каждого снимка (поясничный
  отдел позвоночника или проксимальный отдел бедра) и вероятность нарушения;
- в блоке **«Результат по снимку»** — шкала **вероятности нарушения** от 0 до 1
  (зелёная — низкая, красная — высокая);
- под номером исследования — итоговая оценка («Качественное» / «Есть
  нарушения») и статус проверки; в блоке «Сведения» — **«Модель ИИ»** (версия);
- список находок в панели **«Находки ИИ и эксперта»**: категория
  нарушения, критичность, уверенность и текстовое объяснение (например,
  «наклон оси 6,9° при допустимых 5°»).

Какие нарушения проверяются (по ТЗ и «Разъяснениям» заказчика):

| Область | Нарушение | Как проверяется |
|---|---|---|
| Позвоночник | Некорректная укладка | внизу кадра должны быть видны верхние края подвздошных костей, вверху — половина Th12 (обученная модель) |
| Позвоночник | Не выравнена ось позвоночника | наклон оси больше 5° (с учётом размера пикселя 1,05 × 0,6 мм) |
| Позвоночник | Присутствуют посторонние предметы | металл одежды и др. у краёв кадра (обученная модель) |
| Бедро | Некорректная укладка | позиционирование и ротация (малый вертел) — нейросеть |
| Бедро | Некорректная область интереса | кость обрезана боковым краем кадра |

Кроме того, сервис предупреждает о технических проблемах, которые не входят
в таблицу заказчика: необезличенные данные, отсутствующие обязательные
DICOM-теги, нечитаемые пиксели, грубая смазанность или недоэкспонирование.

**«Повторить ИИ-анализ»** — пересчитать (например, после обновления модели).
Прежний результат ИИ и ваши решения по нему не теряются: они сохраняются в блоке
**«История анализов»** (дата, версия модели, что подтверждено и отклонено и кем).
Новый результат требует новой проверки — статус сбрасывается на «Не проверено».
Если повторный анализ завершился ошибкой, прежний результат остаётся как был.

**«Скачать отчёт DICOM SR»** (блок «Результат по снимку») — текстовый отчёт о
выявленных нарушениях в стандарте DICOM (файл `.sr.dcm`). В нём область,
заключение, вероятность, нарушения с пояснениями и статус экспертной проверки;
отклонённые экспертом находки в отчёт не попадают, добавленные экспертом —
попадают. Отчёт можно загрузить в PACS: он привязан к тому же исследованию и
снимку и откроется рядом с ним.

## 5. Просмотр снимка

Встроенный DICOM-вьюер:
- колесо мыши — масштаб, перетаскивание — сдвиг;
- ползунки центра и ширины окна — яркость и контраст;
- **«Вписать снимок»** — вернуть исходный масштаб;
- снимок показывается в физических пропорциях: пиксель денситометра
  неквадратный (1,05 мм по вертикали × 0,6 мм по горизонтали, либо значения из
  тега PixelSpacing), поэтому видимый наклон оси совпадает с углом, который
  считает ИИ;
- снимки MONOCHROME1 (обратная полярность) приводятся к обычному виду; сжатые
  форматы DICOM вьюер не показывает (с понятным сообщением), анализ при этом работает;
- находки поверх снимка: сплошная рамка — ИИ, пунктир — эксперт; цвет рамки —
  критичность (жёлтый → красный).

## 6. Экспертная проверка

Для каждой находки ИИ в панели справа:
- **«Подтвердить»** — нарушение есть;
- **«Отклонить»** — ложное срабатывание;
- **«Изменить категорию…»** — нарушение есть, но другого типа.

Если ИИ что-то пропустил:
1. **«Выделить область на снимке»** — обведите область зажатой левой кнопкой мыши;
2. выберите категорию нарушения и критичность, при желании добавьте комментарий;
3. **«Сохранить находку»** — она появится с пометкой «Добавлено экспертом».

Когда все находки разобраны, нажмите **«Завершить проверку»** (вверху справа;
кнопка активна, только если исследование проанализировано и по каждой находке ИИ
принято решение — это проверяет и сервер) —
статус исследования станет «Проверено экспертом». Все действия пишутся в
журнал.

## 7. Пакетная обработка набора исследований

Для проверки большого набора и выгрузки таблицы в формате заказчика (одна
строка — один снимок). Исследования при этом в список не добавляются.

**В веб-интерфейсе** — раздел **«Пакетная обработка»**:
1. перетащите zip-архив в рамку (или нажмите на неё и выберите файл);
2. выберите формат таблицы — XLSX или CSV;
3. галочка **«Добавить отчёты DICOM SR»** — результат придёт zip-архивом:
   таблица и папка `sr/` с отчётом по каждому снимку;
4. **«Запустить обработку»** — файл сохранится в папку загрузок браузера,
   на странице появится число обработанных файлов и файлов с ошибкой.

**Командой на сервере:**

```bash
./run.sh batch /путь/к/набору.zip результаты.xlsx          # только таблица
./run.sh batch /путь/к/набору.zip результаты.xlsx --sr     # + отчёты DICOM SR в папке sr/ рядом
```

**Через API** (например, из скрипта):

```bash
curl -X POST "http://<сервер>:8000/batch?format=xlsx" -H "Authorization: Bearer <токен>" \
     -F "file=@набор.zip" -o результаты.xlsx
# таблица + отчёты DICOM SR одним zip-архивом:
curl -X POST "http://<сервер>:8000/batch?format=xlsx&sr=true" -H "Authorization: Bearer <токен>" \
     -F "file=@набор.zip" -o результаты.zip
```

Вход — zip-архив (папки и вложенные архивы допускаются), папка или один
DICOM-файл. Колонки таблицы:

| Колонка | Что значит |
|---|---|
| `path_to_study` | путь к файлу |
| `study_uid`, `image_uid` | идентификаторы исследования и снимка из DICOM |
| `anatomical_region` | область |
| `quality_class` | 0 — качественное, 1 — есть нарушение |
| `quality_prob` | вероятность нарушения, 0…1 |
| `violation_type` | нарушения через «;»; пусто — нарушений нет |
| `processing_status` | `Success` / `Failure` |
| `time_of_processing` | время обработки, с |

Файлы со статусом `Failure` (повреждённые, не DICOM) перечислены с причинами
в файле `результаты.errors.csv` рядом с таблицей.

## 8. Администрирование (роль «Администратор»)

- **«Пользователи»** — создать учётную запись (логин, ФИО, роль, пароль),
  отключить пользователя.
- **«Справочник нарушений»** — добавить тип нарушения, переименовать,
  изменить критичность по умолчанию, включить/отключить. Системные типы и типы,
  которые уже встречаются в находках, нельзя удалить — только отключить; AI ссылается на них по коду, поэтому
  переименование не ломает анализ.
- **«Статистика»** — число исследований, качественных и с нарушениями,
  ожидающих проверки, нарушения по категориям.
- **«Журнал действий»** — кто, когда и что сделал (вход, загрузка, анализ,
  проверка, пакетная обработка).

## 9. Как понимать результат

- AI — это вторая пара глаз, а не окончательное решение. На проверочной
  выборке сервис находит примерно половину исследований с нарушениями
  (чувствительность 0,49) и верно пропускает 82 % качественных
  (специфичность 0,82). Подробно — [КАЧЕСТВО_РЕШЕНИЯ.md](КАЧЕСТВО_РЕШЕНИЯ.md).
- «Вероятность нарушения» удобна для сортировки: исследования с высокой
  вероятностью стоит проверить в первую очередь.
- Сервис обучен на снимках одного аппарата. На снимках другого аппарата
  результаты нужно перепроверять особенно внимательно.
