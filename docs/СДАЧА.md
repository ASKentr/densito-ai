всем материалам.

| **Репозиторий** | Ссылка на публичный Git-репозиторий (открыт для просмотра или гостевой доступ). В корне обязательно `README.md` с инструкцией по локальному запуску | GitHub, аккаунт ASKentr (репозиторий ещё не создан — создаём по команде Рината). README переписать по ТЗ п.5 |

| **Презентация** | Ссылка на слайды (PDF на облачном диске, Яндекс.Диске, Google Slides и т.д.) | PDF презентации — на облачном диске и/или в репозитории |
| **Прототип** | Ссылка на развёрнутый работающий сервис (веб-интерфейс, стенд, тестовый сервер, бот). Для алгоритмических/бэкенд-задач допустимы скринкаст/демонстрация или ссылка на Swagger/тестовый эндпоинт | **Решить:** стенд (например, ВМ Yandex Cloud по гранту SourceCraft) или скринкаст. См. ниже |
| **Дополнительные материалы** | Любые вспомогательные файлы: видеодемонстрация/скринкаст, датасеты, схемы архитектуры, макеты | Скринкаст, схема архитектуры; датасет НЕ выкладываем (медданные, не наши) |

**Ссылки можно дублировать.** Если документация лежит в репозитории, а все
материалы — в одной папке на диске, одну и ту же ссылку можно указать во всех
обязательных полях — главное, чтобы эксперт по ней нашёл нужный артефакт.

## Презентация (дополнение организаторов, получено 2026-09-25)

Наше ТЗ презентацию **требует** (ТЗ п.4, п.7.2) -> готовим **полную
презентацию проекта**: обязательные слайды 7–11 + описательная часть решения.
(Командам, у которых ТЗ презентацию не требует, достаточно только слайдов 7–11.)

Шаблон: `Документация/ЛЦТ2026 Шаблон презентации.pptx`.

Правила оформления:
- **Слайды 7–11 — строго в исходном дизайне и структуре**: сетку, расположение
  блоков и форматирование менять нельзя.
- **Исключение — слайд 10 (состав команды)**: если участников меньше, чем мест
  на слайде, лишние карточки/блоки удалить. У нас 2 человека (Ринат + коллега).
- Слайды до 7-го и после 11-го — на наше усмотрение: можно брендировать под
  продукт, менять структуру и порядок повествования.

Содержание описательной части — ТЗ п.4: подход и обоснование; архитектура
модели и ПО; состав датасета, разбиение выборки, предобработка; таксономия
нарушений и мультилейбл; эксперименты, сравнение вариантов и анализ ошибок;
метрики с 95% ДИ (готово — `docs/КАЧЕСТВО_РЕШЕНИЯ.md`, раздел 0); скорость и
системные требования; ограничения и сценарий внедрения; кейсы.

**Важно: на этапе до 14 октября питчей нет** — эксперты оценивают только
загруженные материалы (код, репозиторий, документацию, презентацию). Значит,
презентация и README должны быть понятны **без устного комментария**: выводы
прямо на слайдах, а не «расскажу на защите».

## Что из этого следует (открытые вопросы)

- **Прототип.** Развёрнутого стенда у нас нет. Варианты:
  1. публичный стенд на ВМ — нужна машина с Docker; на публичном стенде
     обязательно сменить демо-пароли (`BOOTSTRAP_*_PASSWORD`, `SECRET_KEY`) и
     загружать только обезличенные/синтетические снимки;
  2. скринкаст сценария (загрузка → анализ → просмотр → экспертная проверка →
     пакетная обработка через `POST /batch`) — не зависит от стенда, делаем в
     любом случае как страховку.
- ~~Интернет у экспертов~~ — **РЕШЕНО (ответ организаторов, 2026-09-25):**
  «Скачиваться с интернетом, инференс модели локальный». То есть при установке
  зависимости можно докачивать из интернета, а инференс должен идти локально.
  Наше решение этому соответствует: сборка скачивает ~550 МБ (базовые образы
  ~135 МБ, PyTorch ~198 МБ, прочие Python-пакеты ~139 МБ, npm ~30 МБ, пакеты
  Debian), веса моделей лежат в репозитории, во время работы решение в сеть не
  ходит (гибрид больше не скачивает веса ImageNet — `ViolationModel(pretrained=False)`).
  Режим «готовые образы архивом» (`docker save`/`docker load`) не нужен.
- **Swagger.** Страница `/docs` грузит оформление с cdn.jsdelivr.net (публичный
  CDN, не инференс). При наличии интернета работает; без него страница пустая,
  API при этом работает. Локальные файлы Swagger — низкий приоритет.
- **Доступ.** Перед отправкой открыть каждую ссылку в режиме инкогнито (без
  входа в аккаунты) и убедиться, что всё открывается.
