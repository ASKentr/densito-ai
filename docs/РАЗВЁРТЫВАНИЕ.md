# Руководство по развёртыванию Densito-AI

Для инженера, который устанавливает сервис. Кратко о проекте и API —
[README.md](../README.md); работа в интерфейсе — [РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md](РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md).

## 1. Что разворачивается

Два контейнера (`docker-compose.yml`):

| Сервис | Образ | Порт | Что внутри |
|---|---|---|---|
| `backend` | Python 3.11 + PyTorch (CPU) | 8000 | REST API (FastAPI), AI-модуль, пакетная обработка, БД SQLite |
| `frontend` | nginx | 5173 → 80 | собранный веб-интерфейс (React) |

Данные хранятся в томах Docker: `<проект>_backend_data` (БД SQLite) и
`<проект>_backend_storage` (загруженные DICOM). `<проект>` — имя папки
репозитория, список томов — `docker volume ls`.

Инференс полностью локальный: во время работы сервис не обращается к
внешним сервисам и не передаёт изображения. Интернет нужен только при сборке
образов (скачивается ~550 МБ: базовые образы, PyTorch, пакеты Python и npm) —
это согласовано с организаторами.

## 2. Требования

| | Минимум | Рекомендуется |
|---|---|---|
| ОС | Linux x86-64 (или другая UNIX-подобная с Docker) | Ubuntu 22.04/24.04, Debian 12 |
| CPU | 2 ядра | 4+ ядра |
| ОЗУ | 2 ГБ | 4 ГБ |
| Диск | 5 ГБ | 10 ГБ + место под исследования |
| GPU | не нужен | не нужен |
| ПО | Docker Engine 24+, Docker Compose v2 (`docker compose`) или `docker-compose` | — |

Замеры: 0,15 с на исследование в среднем, пиковая память пакетной
обработки ~0,4 ГБ (Intel i5-1145G7, 4 ядра).

Установка Docker на Ubuntu/Debian — по официальной инструкции
<https://docs.docker.com/engine/install/>; чтобы запускать без `sudo`:
`sudo usermod -aG docker $USER` и перелогиниться.

## 3. Установка и первый запуск

```bash
git clone https://github.com/ASKentr/densito-ai.git densito-ai
cd densito-ai
./run.sh up
```

Если `./run.sh` не запускается с ошибкой прав: `chmod +x run.sh`.

При первом запуске скрипт создаёт файл `.env` с настройками (случайный
`SECRET_KEY`, пароли демо-учёток, порты, адреса), собирает образы (несколько
минут) и запускает контейнеры. В конце печатает адреса:

```
Densito-AI запущен:
  веб-интерфейс:     http://localhost:5173
  API и Swagger:     http://localhost:8000/docs
```

Проверка работоспособности:

```bash
curl http://localhost:8000/health        # {"status":"ok",...}
./run.sh status                          # оба контейнера в состоянии running/Up
```

### Доступ с других компьютеров

Адрес backend, по которому к нему обращается **браузер пользователя**,
вшивается в веб-интерфейс при сборке. Поэтому, если сервис будут открывать
не с того же компьютера, укажите адрес сервера **при первом запуске**:

```bash
PUBLIC_HOST=10.0.0.5 ./run.sh up         # или доменное имя
```

Если `.env` уже создан — поправьте в нём `API_PUBLIC_URL` и `CORS_ORIGINS` и
пересоберите: `./run.sh up`.

## 4. Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | случайный (генерирует `run.sh`) | ключ подписи токенов входа |
| `BOOTSTRAP_ADMIN_PASSWORD` | `admin12345` | пароль учётки `admin` при **первом** старте |
| `BOOTSTRAP_EXPERT_PASSWORD` | `expert12345` | пароль учётки `expert` при **первом** старте |
| `BACKEND_PORT` / `FRONTEND_PORT` | `8000` / `5173` | порты на хосте |
| `API_PUBLIC_URL` | `http://<PUBLIC_HOST>:8000` | адрес backend для браузера (вшивается при сборке frontend) |
| `CORS_ORIGINS` | JSON-список адресов веб-интерфейса | с каких адресов браузер может обращаться к API |
| `MAX_UPLOAD_MB` | `2048` | лимит одного загружаемого файла (zip или DICOM), иначе 413 |
| `MAX_UNPACKED_MB` | `8192` | лимит объёма архива после распаковки (вместе с вложенными) — защита от «ZIP-бомб» |
| `MAX_ARCHIVE_FILES` | `50000` | лимит числа файлов в архиве |

Демо-учётки создаются, только если БД пустая. Смены пароля в интерфейсе нет:
чтобы применить новые пароли к уже запущенному сервису, выполните
`./run.sh reset` (удалит все данные) и `./run.sh up`. Другой путь —
администратор создаёт новые учётные записи со своими паролями
(«Пользователи») и отключает демо-учётки.

**Если сервис доступен из интернета** (стенд для демонстрации):
1. до первого запуска смените `BOOTSTRAP_*_PASSWORD` в `.env`;
2. не публикуйте `.env`;
3. загружайте только обезличенные или синтетические снимки;
4. поставьте перед сервисом обратный прокси с HTTPS (nginx, Caddy, Traefik) —
   сам сервис TLS не терминирует.

## 5. Пакетная обработка

```bash
./run.sh batch /data/test_set.zip /data/results.xlsx
./run.sh batch /data/studies_folder results.csv
```

Скрипт монтирует входные данные в контейнер только для чтения, результат
пишет от имени текущего пользователя. Рядом с таблицей при ошибках
появляется `results.errors.csv`. Контейнер сервиса для этого запускать не
обязательно — `batch` работает и при остановленном `up`.

То же через REST API — `POST /batch` (см. README, раздел 6).

## 6. Обслуживание

| Задача | Команда |
|---|---|
| Остановить / запустить | `./run.sh down` / `./run.sh up` |
| Журналы | `./run.sh logs` |
| Обновить до новой версии | `git pull && ./run.sh up` (образы пересоберутся, данные сохранятся) |
| Удалить всё, включая данные | `./run.sh reset` |

Резервная копия данных (БД и загруженные исследования):

```bash
docker run --rm -v densito-ai_backend_data:/data -v densito-ai_backend_storage:/storage \
    -v "$PWD":/backup alpine tar czf /backup/densito-backup.tgz /data /storage
```

Восстановление — та же команда с `tar xzf` в обратную сторону при
остановленном сервисе. Имена томов уточните через `docker volume ls`.

## 7. Запуск без Docker

Для разработки или если Docker недоступен:

```bash
cd backend
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements-model.txt -c requirements.lock
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

cd ../frontend                         # Node.js 20.19+ или 22.12+
npm ci
VITE_API_BASE=http://localhost:8000 npm run build   # статика в dist/ — отдать любым веб-сервером
npm run dev                            # или режим разработки на :5173
```

Пакетная обработка без Docker: `cd backend && python batch_predict.py <вход> <результат.xlsx>`.
Режим без нейросети (не нужен PyTorch): `--engine heuristics` и
`pip install -r requirements.txt -c requirements.lock`.

## 8. Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| `не найден Docker Compose` | установите Docker Engine и плагин compose |
| `permission denied ... docker.sock` | пользователь не в группе `docker`: `sudo usermod -aG docker $USER`, перелогиниться |
| `port is already allocated` | порт 8000 или 5173 занят — поменяйте `BACKEND_PORT`/`FRONTEND_PORT` в `.env` (и порт в `API_PUBLIC_URL`, `CORS_ORIGINS`), `./run.sh up` |
| Интерфейс открывается, но вход не работает / «Network Error» | браузер обращается к неверному адресу API или его блокирует CORS: проверьте `API_PUBLIC_URL` и `CORS_ORIGINS` в `.env`, затем `./run.sh up` (frontend пересоберётся) |
| Страница `/docs` пустая | нет доступа в интернет из браузера: оформление Swagger грузится с публичного CDN; сам API работает |
| Не входят `admin12345`/`expert12345` | пароли были изменены в `.env` до первого запуска (смотрите `.env`) или демо-учётки отключены администратором |
| Файлы в таблице со статусом `Failure` | причины — в `<результат>.errors.csv` (не DICOM, повреждён, не удалось определить область) |
| Сборка падает на скачивании пакетов | нет интернета при сборке или недоступен PyPI / download.pytorch.org / Docker Hub — повторите при доступной сети |
