# Обучение и дообучение модели Densito-AI

Для ML-инженера. Как устроено решение — [README.md](../README.md), раздел 8;
почему нейросеть применяется только для укладки бедра — [ГИБРИД_МОДЕЛЬ.md](ГИБРИД_МОДЕЛЬ.md);
метрики — [КАЧЕСТВО_РЕШЕНИЯ.md](КАЧЕСТВО_РЕШЕНИЯ.md).

## 1. Что обучается

| Компонент | Файл весов | Скрипт обучения | Время на CPU |
|---|---|---|---|
| Скореры позвоночника: укладка, посторонние предметы, «есть нарушение» — 3 логистические регрессии | `backend/ai_module/weights/spine_scorers.json` | `fit_spine_scorers.py` | быстро: numpy, без GPU |
| CNN (ResNet18, 2 головы) — в боевом решении используется для укладки бедра | `backend/ai_module/weights/violation_model.pt` (45 МБ) | `model_train_final.py` | несколько минут |
| Порог CNN | константа `POSITIONING_THRESHOLD` в `hybrid.py` | печатает `eval_pipeline_cv.py` | — |

Остальное — правила по критериям ТЗ без обучения: ось позвоночника > 5°,
область интереса бедра (кость у бокового края кадра), определение области по
симметрии. Их пороги — константы в `heuristics.py`.

## 2. Данные

Разметка заказчика — `разметка.xlsx`, лист «Калибровка», строки 3–102 (шапка
в две строки), значения 0 — норма, 1 — нарушение:

| Колонка | Поле |
|---|---|
| B | `study` — совпадает с именем папки исследования |
| C, D, E | позвоночник: укладка / ось выровнена (до 5°) / посторонние предметы |
| F, G | правое бедро: позиционирование-ротация / область интереса |
| H, I | левое бедро: то же |

Снимки — `Исследования/<study>/.../*.dcm`. Разбор — `ai_module/labels.py`.

Метки даны на уровне исследования и области, а обучение — на уровне снимка
(`ai_module/model_data.py`): область снимка определяется классификатором по
симметрии; для бедра сторона снимка неизвестна, поэтому поле берётся, только
если оценки правого и левого бедра совпадают (иначе снимок для этого поля
исключается).

Датасет в репозиторий не входит (обезличенные медицинские данные
организатора). Если распаковываете `Датасет.zip` вручную — имена внутри
вложенных архивов в кодировке cp866 (пакетная обработка `ai_module/batch.py`
декодирует их сама).

## 3. Окружение

```bash
cd backend
pip install -r requirements-model.txt -c requirements.lock
```

При обучении CNN torchvision **скачивает из интернета** предобученные веса
ImageNet для ResNet18 (~45 МБ, один раз, в кэш `~/.cache/torch`). Для
инференса это не нужно: боевой код создаёт сеть без них и загружает свои веса.

Ниже `XLSX` и `STUDIES` — пути к разметке и папке исследований, команды
выполняются из папки `backend/`:

```bash
XLSX="../_extract/НД_для_обучения/разметка.xlsx"
STUDIES="../_extract/НД_для_обучения/Исследования"
```

## 4. Полный цикл переобучения

```bash
# 0. проверить, что разметка связывается со снимками (печатает сводку)
python -m ai_module.labels "$XLSX" "$STUDIES"
python -m ai_module.model_data "$XLSX" "$STUDIES"

# 1. скореры позвоночника: веса + кросс-валидация (20 повторов 5-fold по исследованиям)
python -m ai_module.fit_spine_scorers "$XLSX" "$STUDIES"
#    -> ai_module/weights/spine_scorers.json, ../docs/spine_scorers_cv.json

# 2. CNN: кросс-валидация 5 фолдов по исследованиям (5 × 12 эпох, ~15–20 мин на CPU)
python -m ai_module.model_train "$XLSX" "$STUDIES"
#    -> ../_extract/model_vs_heuristic_report.json, ../_extract/model_vs_heuristic_raw.json (OOF)
python -m ai_module.bootstrap_ci
#    -> ../docs/model_vs_heuristic_ci.json (95 % ДИ, модель vs эвристика по каждому полю)

# 3. CNN: финальное обучение на всех данных
python -m ai_module.model_train_final "$XLSX" "$STUDIES" ai_module/weights/violation_model.pt

# 4. порог CNN во вложенной кросс-валидации (5 внешних × 4 внутренних фолда,
#    20 обучений CNN, ~1 ч на CPU) -> ../docs/cnn_nested_thresholds.json
python -m ai_module.nested_threshold "$XLSX" "$STUDIES"

# 5. итоговые метрики всего решения (порог каждого фолда — из вложенной CV)
python -m ai_module.eval_pipeline_cv "$XLSX" "$STUDIES" ../_extract/model_vs_heuristic_raw.json \
    --nested ../docs/cnn_nested_thresholds.json
#    печатает «порог CNN по правилу на всех OOF: X» — если отличается от
#    hybrid.POSITIONING_THRESHOLD, скрипт предупредит: обновите константу
#    -> ../docs/pipeline_cv.json

# 6. проверка
pip install -r requirements-dev.txt -c requirements.lock
python -m pytest tests/ -q
python batch_predict.py "../_extract/Для теста" /tmp/check.xlsx
```

## 5. Принципы, которые нельзя нарушать

- **Разбиение только по исследованиям** (`group_kfold` в `model_train.py`,
  seed 42). Снимки одного исследования в обучении и проверке одновременно дают
  завышенные метрики.
- **Порог — по правилу, а не подбором под метрику.** Для скореров и CNN
  доля помеченных = доля нарушений в обучающих данных. При оценке порог
  каждого фолда берётся из вложенной кросс-валидации (`nested_threshold.py`):
  его считают модели, которые этот фолд не видели ни прямо, ни через обучение.
- **Решения — по доверительным интервалам.** На 12–47 позитивах точечные
  оценки обманчивы: при первом прогоне CNN казалась лучше и для укладки
  позвоночника, но с ДИ разница оказалась шумом. Переключать компонент на
  модель стоит, только если ДИ модели и альтернативы не пересекаются
  (`bootstrap_ci.py`).
- **Признаки скореров одни для обучения и инференса** — функция
  `learned_scorers.spine_features`; не дублировать.

## 6. Дообучение на новых данных

**Больше исследований того же аппарата.** Добавьте строки в `разметка.xlsx`
в том же формате (если строк больше 100 — поправьте `LAST_DATA_ROW` в
`labels.py`), положите папки исследований рядом и выполните полный цикл
(раздел 4). Сравните новые метрики с `docs/КАЧЕСТВО_РЕШЕНИЯ.md`, раздел 0.

**Другой аппарат.** Кроме переобучения проверьте:
1. размер пикселя: при отсутствии тегов PixelSpacing используются константы
   `calibration.py` (1,05 × 0,6 мм — только для текущего аппарата);
2. классификатор области: порог `REGION_SYMMETRY_THRESHOLD` в `heuristics.py`
   (калибровался на этом аппарате);
3. домен скореров позвоночника: `learned_scorers.in_domain` (кадры 150–400 px);
   вне домена скореры отключаются и работают правила без обучения;
4. пороги резкости/экспозиции `heuristics.py` (выдают только
   предупреждения в веб-интерфейсе, в таблицу не попадают).

**Нарушение «Некорректная область интереса» бедра** — сейчас 1 пример в
разметке. Первое, что стоит сделать при появлении данных, — собрать
размеченные примеры и заменить правило «кость у края кадра» на проверку
расстояний ТЗ (3 см сверху и снизу, 2 см сбоку от области интереса).

## 7. Как подключить другую модель

Backend и веб-интерфейс обращаются к AI только через контракт: структуры
данных `ai_module/interface.py` (`AIStudyResult`, `AIImageReport`, `AIFinding`)
и две функции модуля-движка с той же сигнатурой, что в `heuristics.py` и
`hybrid.py`: `analyze_study(paths) -> AIStudyResult` и
`analyze_image(index, path) -> (AIImageReport, list[AIFinding])`. Новая модель
реализует этот контракт; переключение — импорт в `app/routers/studies.py` и
движок в `ai_module/batch.py::load_engine`.
