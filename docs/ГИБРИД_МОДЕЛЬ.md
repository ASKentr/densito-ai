# Гибрид CNN+эвристики — боевой движок решения

Статус: **ВКЛЮЧЁН для сдачи** (решение команды 2026-09-24). Раньше (2026-09-23)
по умолчанию стояли чистые эвристики — из-за веса зависимостей и того, что
выигрыш модели выглядел статистически некрепким. После ДИ и исправления
классификатора региона выигрыш на укладке бедра подтверждён (AUC 0.850
[0.742, 0.932] против 0.547), а без CNN бедро (61% снимков) остаётся на уровне
случайности — см. `docs/КАЧЕСТВО_РЕШЕНИЯ.md`. Ограничений по размеру образа у
команды нет.

## Где включено

- `backend/app/routers/studies.py` — веб-сервис импортирует
  `ai_module.hybrid.analyze_study` (единственное место в `backend/app/`).
- `backend/batch_predict.py` — `--engine hybrid` по умолчанию.
- `backend/Dockerfile` — ставит `requirements-model.txt` (torch/torchvision CPU,
  сборки для Python 3.11 под Linux проверены на download.pytorch.org).
- `backend/ai_module/weights/violation_model.pt` (44.8 МБ) — обученные веса,
  **теперь обязательная часть сдачи** (ТЗ п.7.2).

**Работа без интернета.** `ViolationModel(pretrained=False)` в `hybrid.py`:
раньше при создании модели torchvision скачивал веса ImageNet (на машине
разработки они лежали в кэше, поэтому проблема не проявлялась). В контейнере
без сети гибрид бы не загрузился, и все снимки бедра получили бы Failure; к
тому же ТЗ запрещает внешние обращения. Проверено 2026-09-24 с пустым
`TORCH_HOME`: 499/499 Success, кэш пуст, таблица построчно совпадает с
прежним гибридным прогоном. `pretrained=True` (по умолчанию) нужен только
для обучения.

**Порог флага укладки бедра** — `hybrid.POSITIONING_THRESHOLD = 0.2735`
(было 0.5, изменено 2026-09-25). ТЗ порога не задаёт; правило — доля
помеченных снимков равна доле нарушений в разметке (квантиль OOF-вероятностей
CNN), как у скореров позвоночника. Честная CV (порог фолда — без его данных):
чувствительность укладки бедра 0.32 -> 0.47, специфичность 0.94 -> 0.89,
F1 0.41 -> 0.47. Цифры и оговорки — `docs/КАЧЕСТВО_РЕШЕНИЯ.md`, раздел 0.
При переобучении CNN порог пересчитать: `eval_pipeline_cv.py` печатает значение
по правилу и предупреждает о расхождении с константой.

## Как откатиться на чистые эвристики

- веб: в `studies.py` импортировать `analyze_study` из `ai_module.heuristics`;
- CLI: `python batch_predict.py <папка> <результат.xlsx> --engine heuristics`
  (torch не нужен).

`backend/tests/test_ai_module.py` написаны против `heuristics` напрямую —
гибрид проверялся smoke-тестом API и прогоном на «Для теста» / обучающей
выборке (2026-09-24).

## Почему включили только укладку бедра (не позвоночника)

Обновлено 2026-09-23 после фикса классификатора региона (шаг 1 — раньше он
путал сильно смещённые снимки позвоночника с бедром, см.
`docs/СТАТУС_ПРОГРЕССА.md`) и добавления 95%-бутстрэп-ДИ (`bootstrap_ci.py`,
ресэмплинг ПО ИССЛЕДОВАНИЯМ, 2000 итераций). Точечные AUC —
`docs/model_vs_heuristic_report.json`, интервалы — `docs/model_vs_heuristic_ci.json`:

| Поле | positives | Модель AUC [95% ДИ] | Эвристика AUC [95% ДИ] | Что лучше |
|---|---|---|---|---|
| spine.incorrect_positioning | 12 | 0.516 [0.321, 0.810] | 0.467 [0.249, 0.642] | **Ни один** — ДИ перекрываются и оба пересекают 0.5 |
| spine.axis_misaligned | 23 | 0.532 [0.345, 0.677] | 0.777 [0.629, 0.881] | Эвристика — ДИ не пересекаются |
| spine.artifact | 38 | 0.598 [0.411, 0.866] | 0.502 [0.458, 0.569] | Ни один надёжно — оба ДИ пересекают 0.5, перекрываются |
| hip.incorrect_positioning | 47 | **0.850 [0.742, 0.932]** | 0.547 [0.390, 0.687] | **Модель** — ДИ не пересекаются, единственный надёжный случай |
| hip.incomplete_field_of_view | 1 | 0.496 [0.364, 0.604] | 0.585 [0.446, 0.704] | Ни один — 1 позитив на весь датасет |

`hybrid.py` v0.2 реализует именно это: CNN подключается только для
`hip.incorrect_positioning`. Для `spine.incorrect_positioning` раньше
казалось, что модель выигрывает (точечная оценка 0.670 vs 0.516 в первом
прогоне) — после исправления классификатора региона (более чистая
разметка, n_positive не изменился, но состав выборки — да) эта разница
исчезла и её ДИ показывают, что она изначально была шумом на 12 позитивах,
а не реальным эффектом. Хороший урок: точечная оценка на 6-47 позитивах
без ДИ — ненадёжное основание для архитектурного решения.

## Если веса устарели или нужно переобучить

Датасет для обучения — `_extract/НД_для_обучения/` (не в репозитории,
персональные медицинские данные, распаковывается из
`Документация/Датасет.zip`, см. `backend/ai_module/labels.py`).

```
cd backend
python -m ai_module.model_train_final "../_extract/НД_для_обучения/разметка.xlsx" "../_extract/НД_для_обучения/Исследования" "ai_module/weights/violation_model.pt"
```

Полная кросс-валидация (для пересчёта таблицы сравнения выше) —
`python -m ai_module.model_train ...` с теми же двумя первыми аргументами;
5 фолдов × 12 эпох на CPU занимает ~15-20 минут.

## Решение по судьбе весов (2026-09-23)

44.8 МБ бинарник весов — **коммитить как обычный git-файл, без LFS**.
Причины:
- 44.8 МБ далеко от практических лимитов git (мягкий порог GitHub ~50МБ,
  жёсткий — 100МБ) и это финальный артефакт, а не файл, который часто
  меняется в разработке — риск разрастания истории репозитория минимален.
- Git LFS для этой задачи рискованнее: если платформа сдачи (SourceCraft/
  Yandex Cloud, см. `Документация/Комментарии.txt`) не настроит `git lfs
  pull` при клонировании, эксперты получат вместо весов текстовый
  pointer-файл — тихая порча без явной ошибки. Обычный git-блок этого
  риска не несёт.
- По ТЗ (п.7.2) обученную модель и веса обязательно включать в финальную
  сдачу. С 2026-09-24 гибрид — боевой движок, так что веса **обязательны**:
  без них решение не работает.

Файл сейчас untracked, ничего не мешает включить его в `git add` при
следующем коммите — `.gitignore` его не исключает.
