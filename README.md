# Densito-AI

Сервис искусственного интеллекта по оценке качества исследований денситометрии
(DXA) — автоматизированная проверка качества DICOM-изображений и корректности
разметки анатомических структур, с веб-интерфейсом для загрузки исследований,
просмотра результатов AI и экспертной проверки.

Проект сделан по ТЗ хакатона (см. `docs/`) и реализует полный сценарий:

```
Загрузить DICOM → запустить AI-анализ → получить оценку → увидеть ошибки
на снимке → провести экспертную проверку → сохранить результат
```

## Статус на данный момент

Рабочий full-stack MVP: backend, AI-модуль и веб-интерфейс реализованы и
покрывают весь сценарий из ТЗ (см. `docs/tz.md`). Реальных обезличенных
денситометрических DICOM с экспертной разметкой пока нет — они появятся от
заказчика позже. Чтобы не ждать данных, весь пайплайн (парсинг DICOM,
обезличивание, вьюер, эвристики качества, БД, UI) уже сейчас проверен на
**синтетических** DICOM-исследованиях (`sample_data/`), сгенерированных
скриптом, а также на настоящих сторонних DICOM-файлах (тестовые данные
pydicom) — для проверки, что парсер не ломается на «чужих» файлах.

Как только появятся настоящие исследования — просто загрузите их через
интерфейс (или положите в `sample_data/real_studies/`). Ничего в коде менять
не нужно: AI-модуль работает с любым корректным DICOM.

## Архитектура

```
┌──────────────┐      REST/JSON      ┌───────────────┐     вызов функции    ┌──────────────┐
│   Frontend   │ ───────────────────▶│    Backend     │ ────────────────────▶│  AI-модуль   │
│ React + Vite │◀─────────────────── │    FastAPI     │◀──────────────────── │ (heuristics) │
└──────────────┘                     │ SQLite + JWT   │                      └──────────────┘
                                      └───────┬────────┘
                                              │
                                        DICOM-файлы на диске
```

Ключевое архитектурное решение (п.8 ТЗ — возможность заменить AI-модель без
переделки веб-интерфейса): backend обращается к AI **только** через
контракт `ai_module/interface.py` (`analyze_study(paths) -> AIStudyResult`).
Сегодня `ai_module/heuristics.py` реализует его через классическое
компьютерное зрение (OpenCV/NumPy/SciPy) — без обучения, но с реальным
анализом пикселей, а не заглушкой. Когда появится датасет с экспертной
разметкой, `heuristics.py` можно заменить на вызов обученной модели (или на
HTTP-клиент к отдельному inference-сервису) — backend, БД и веб-интерфейс не
изменятся.

### Backend (`backend/`)

- FastAPI + SQLModel (SQLite по умолчанию, легко переключить на Postgres).
- JWT-авторизация, роли `admin` / `expert` (п.7 ТЗ).
- Загрузка одиночных DICOM и ZIP-архивов, автоматическая проверка
  обезличивания (поиск PHI-тегов: ФИО, дата рождения и т.п.).
- Хранение исследований/изображений/находок/экспертных правок/аудит-лога.
- Редактируемый администратором справочник нарушений (`ViolationType`) —
  AI и backend ссылаются на него по устойчивому `code`, а не по id/названию.
- Полный REST API: `/auth`, `/studies`, `/findings`, `/admin/*`
  (интерактивная документация на `/docs` после запуска).

### AI-модуль (`backend/ai_module/`)

Что реально считается по пикселям (не заглушка):

| Проверка | Метод |
|---|---|
| Резкость / смазанность | variance of Laplacian на нормализованном изображении |
| Экспозиция / контраст | std сырых значений пикселей (до windowing) |
| Позиционирование / обрезка поля | сегментация Otsu + связные компоненты → bbox, касание края кадра |
| Наклон (для вытянутых структур, напр. позвоночник) | PCA главной оси маски, отклонение от вертикали |
| Артефакты | яркие связные компоненты вне основной анатомической области |
| Технические ошибки DICOM | обязательные теги, декодируемость PixelData |
| Обезличивание | проверка PHI-тегов (ФИО, дата рождения, адрес и т.п.) |
| ROI/сегментация (`roi_segmentation_error`) | **точка расширения** — нужна эталонная экспертная разметка, которой пока нет; см. комментарий `compare_roi_with_reference` в `heuristics.py` |

Пороги калибровались на `sample_data/` (см. `backend/tests/test_ai_module.py` —
10/10 тестов проходят, включая устойчивость к нечитаемым файлам).

### Frontend (`frontend/`)

React + TypeScript + Vite, без тяжёлых UI-фреймворков.

- Логин, список исследований с поиском и фильтрами (п.3 ТЗ).
- Карточка исследования (п.4 ТЗ): общая информация, DICOM-вьюер, результат AI.
- **DICOM-вьюер собственной разработки** (`components/DicomViewer.tsx`):
  парсинг DICOM прямо в браузере (`dicom-parser`), рендер в `<canvas>`,
  масштабирование колесом мыши, перемещение (drag), регулировка
  яркости/контрастности (window center/width), оверлей находок AI и эксперта
  прямо на снимке. Не завязан на cornerstone.js/сторонние вьюер-фреймворки —
  меньше версионных конфликтов, полный контроль над отрисовкой разметки.
- Экспертная проверка (п.5 ТЗ): подтвердить/отклонить/изменить категорию
  находки AI, выделить область на снимке и добавить свою находку,
  комментарии.
- Админ-панель (п.7 ТЗ): справочник нарушений, пользователи, статистика и
  журнал действий.

## Быстрый старт

### Вариант 1 — Docker Compose (рекомендуется для демонстрации)

```bash
docker compose up --build
```

- Backend: http://localhost:8000 (Swagger-документация: `/docs`)
- Frontend: http://localhost:5173

### Вариант 2 — руками (для разработки)

```bash
# Backend
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000

# Frontend (в отдельном терминале)
cd frontend
npm install
npm run dev
```

При первом старте backend сам создаёт БД, сеет справочник нарушений и два
демо-аккаунта:

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin12345` | Администратор |
| `expert` | `expert12345` | Эксперт |

(Пароли задаются через переменные окружения `BOOTSTRAP_ADMIN_PASSWORD` /
`BOOTSTRAP_EXPERT_PASSWORD` — для боевого использования обязательно смените.)

### Тестовые DICOM-исследования

```bash
python sample_data/generate_synthetic_studies.py
```

Генерирует в `sample_data/studies/` 9 синтетических исследований (норма +
7 типов нарушений из справочника, включая необезличенные данные и битые
DICOM-теги) и ZIP-архив со всеми ими — для проверки загрузки архивом.
Манифест `manifest.json` содержит ожидаемый вердикт для каждого файла —
на нём и проверяется AI-модуль (`backend/tests/test_ai_module.py`).

## Тесты

```bash
cd backend
python -m pytest tests/ -v                  # AI-модуль на синтетических данных
python tests/smoke_test_api.py               # сквозной прогон через HTTP API
python tests/e2e_browser_check.py             # сквозной прогон через настоящий браузер (Playwright)
```

Все три уровня проверки пройдены на этой версии кода: юнит-тесты AI-модуля
(10/10), сквозной API-сценарий и сквозной браузерный сценарий (загрузка →
анализ → просмотр → экспертная проверка → сохранение) без ошибок в консоли.

```

  src/api/        — типы и HTTP-клиент
  src/auth/       — контекст авторизации

```

## Известные ограничения и что делать дальше

1. **Реальных данных нет** — как только появятся обезличенные денситометрические
   исследования с экспертной разметкой, нужно: (а) прогнать их через текущий
   эвристический движок и посмотреть на расхождения с разметкой эксперта,
   (б) при необходимости — обучить настоящую модель и подключить её через
   контракт `ai_module/interface.py`, не трогая backend и веб-интерфейс.
2. **ROI/сегментация не реализована по-настоящему** — нужна эталонная
   разметка для сравнения (см. точку расширения в `heuristics.py`).
3. **SQLite** — достаточно для демонстрации; для продакшна переключить
   `DATABASE_URL` на Postgres (SQLModel/SQLAlchemy это поддерживают без
   изменений в коде моделей).
4. **Безопасность (п.9 ТЗ)**: авторизация, роли и журналирование действий
   реализованы; HTTPS/TLS и защищённое хранение файлов — задача внешнего
   деплоя (реверс-прокси, шифрование диска), не самого приложения.
